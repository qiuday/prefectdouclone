# 动作段（28050 维）结构与对拍结论

> 对象：PerfectDou 三个 onnx（输入 `[batch, 32738]`，输出 `action_logit [batch, 621]`）
> 输入 = obs 段 **4688** + 动作段 **28050**（150 行 × 187 维）
> 本文只讲后 28050 维。obs 段见 `obs_structure_v2.md`。
> 实现：`tools/movegen_py.py`（合法动作枚举）、`tools/action_encoder.py`（187 维编码、`build_x` 拼 32738）

## 1. 动作段是什么

每一行 = **一个合法动作**（含 pass），共 150 行上限；只填前 `len(legal)` 行，其余全 0。

行顺序 = 官方 `MovesGener.gen_moves()` 的生成顺序，**不是** id 升序：

```
单张 → 对子 → 三张 → 炸弹 → 王炸 → 三带一 → 三带二
→ 顺子 → 连对 → 飞机 → 飞机带单 → 飞机带对 → 四带二 → 四带二对
```

带牌压牌时只生成与上家同牌型（同长度）的动作 + 炸弹 + 王炸，pass 追加在**最后一行**。
（`legal_moves_with_pass` 里 `last_move` 非空才追加 `[]`。）

## 2. 187 维逐列布局

| 列 | 内容 | 说明 |
|----|------|------|
| 0 | 621 动作 id | 需**两级映射**，见第 3 节；查不到 → 整行全零 |
| 1 | 炸弹 / 王炸标记 | type 4（炸弹）与 type 5（王炸）为 1，其余 0 |
| 2 | 外面压不住 | `legal_moves(other_hand_cards, 这手牌)` 为空 → 1；真机盲牌时 other 为空 → 恒 1 |
| 3 / 4 | **未解** | 官方偶尔为 1，依赖**上家 / 下家各自**的牌分配；程序恒填 0（影响约 0.2% 行） |
| 5 | `min_steps(出掉这手后的剩牌) / 10` | pass 行 = `min_steps(当前手牌) / 10`；值域 0.1~1.2（12 档） |
| 6 | 恒 1.0 | 全数据无非 1 样本 |
| 7..186 | `card_frame(动作牌)` | 180 维，与 obs 帧**同一函数**（块A 累积 / 块B 恰好 / 块C 链） |

## 3. 621 动作 id：两级映射

```
具体牌排序拼串   '35888999'
   └─ specific_map.json（27472 项） → 抽象串 '888999**'
        └─ action_space.json（621 项） → id 517
```

只查 `action_space` 会漏掉飞机带翅膀、四带二等 44 类；必须先用 `specific_map` 归一。

**官方 quirk**：`specific_map` 里没有的组合（典型：四张炸弹带大小王，如 `[9,9,9,9,20,30]`），
`.so` 会给出**整行全零**（id=0、行和为 0）。实测 20 局随机对局出现 2 次（约 0.09% 动作）。
程序必须照做（`action_id()` 返回 `None` → 该行不填），否则模型输入与官方不一致。

621 空间分段：solo 0-14、pair 15-27、trio 28-40、三带一 41-222、三带二 223-378、
顺子 379-414、连对 415-466、飞机 467-511、飞机带单 512-549、飞机带对 550-579、
四带二 580-592、四带二对 593-605、炸弹 606-618、王炸 619、pass 620。

## 4. 对拍结果（对 `.so` 金标准）

**单点对拍**：1600 样本（200 + 600 + 800，三视角）× 每样本的合法动作行，共 **5459 行**：

| 指标 | 结果 |
|------|------|
| 行级完全一致（187 位全同） | **5436 / 5459 = 99.58%** |
| 位级错误 | 23 位 / 1,020,833 位 = **0.0023%** |
| 差异分布（列） | `{2: 10, 3: 2, 4: 9, 5: 2}` |
| 合法动作集合与顺序 | 600/600 样本完全一致 |
| pass 行 head[5] | 457/457 一致（= min_steps(hand)/10） |
| head[1]（炸弹/王炸） | 全对，无遗漏 |
| head[2]（外面压不住） | 抽样 435 行零反例；全量仅 10 行偏差（长顺子，见第 5 节） |

**整链对拍**（`./.so 编码 + onnx`  vs  `纯 Python 编码 + onnx`，逐步比 `argmax` 的动作）：

| 规模 | 步数 | 动作一致 | 一致率 |
|------|------|----------|--------|
| 3 局（seed 0） | 227 | 224 | 98.68% |
| 50 局（seed 11） | 3152 | 3136 | **99.49%** |
| 1000 局（seed 2025） | 61,803 | 61,600 | **99.67%** |

对比口径：两边都把 `other_hand_cards` 置空（盲牌，真机视角），差异只来自编码本身。

1000 局共 61,803 步、203 步动作不同（0.33%）。逐位诊断已证实这些步的差异**全部**落在
`4686`（炸弹位）与动作段列 2/3/4，obs 段其余位为 0 差异 —— 即编码细节差异，链路本身没有错。

> 验收结论：**1000 局动作一致率 99.67% ≥ 99%**，C2 达标。

## 5. 已知偏差（不要当 bug 反复追）

1. **列 3 / 列 4**（11/5459 行）：只在 `last_move` 为空 + 长链（连对 8 张、顺子 6 张、飞机带翅膀 10 张）
   出现。受控实验证明它依赖 `all_handcards` 里**上家 / 下家各自的分配**，不是合并的 outside；
   把 34 张 other 随意切成 17/17 就会在这几行出错。盲牌真机拿不到这个分配，程序恒填 0。
2. **列 2 的 10 行**：集中在同一局的长顺子（5~11 张），程序判"能压"、官方"压不住"。
   口径差异未查明，占比 0.18% 行。
3. **列 5 的 2 行**：`min_steps` 在这两个局面的取值与官方差一档（其余 5457 行全对）。
4. **4686 炸弹位**：见 `obs_structure_v2.md`，`王炸 + 普通炸` 时官方比自算多 1（10/1600 样本）。

以上四类合计让整链一致率停在 99.4%~99.5%，而不是 100%。
验收线是 ≥99%，已达到；若要压到 99.9%+，只剩这几处需要继续解。

## 6. 复现（需要官方 `.so`，只能在 Linux + py3.7 跑）

```bash
# 环境：/tmp/py37（py3.7.12 + onnxruntime 1.7.0 + numpy 1.21.6）
cd /tmp/PerfectDou    # 必须：encode 的 .so 按相对路径 dlopen
/tmp/py37/bin/python tools/chain_check.py --repo /tmp/PerfectDou --games 1000 --seed 2025
```

`chain_check.py` 每步做两次推理：`gold` 用 `encode_obs_landlord/peasant`（.so），
`mine` 用 `obs_py.encode_x_no_action` + 本目录 `action_encoder` 的同一套规则，
两边取 `argmax(logit[:len(legal)])`，用 gold 的动作推进对局，统计一致率。
